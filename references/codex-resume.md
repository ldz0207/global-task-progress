# 在现有看板继续 Codex 对话

这是可选的 Windows Codex 桌面功能，复用现有进度服务、端口和本地状态目录。记录器是服务中的一个线程；发送只在用户点击看板按钮时开始，关闭浏览器页面不终止服务或已提交的 Codex 工作。

## 开启与使用

用户明确要求记录和续接后，为已有数据目录配置：

```powershell
& $progressPython scripts/task_progress.py configure-codex --state-dir '<现行数据目录>' --enable-codex
# 非默认 CODEX_HOME 时另加 --codex-home '<实际Codex本机目录>'
```

启用配置后需要通过原来的服务控制入口重新启动同一看板服务，使其加载功能。保留端口、任务文件、外部来源和正在执行的业务 worker；不并行启动另一套服务。该功能自身不安装独立 GUI、桌面按钮或登录启动项。用户需要登录后记录时，应让原有进度服务启动入口负责启动同一个服务。

照常使用 Codex。重开应用后，在进度页面的“Codex 对话续接”区点击“继续退出前的对话”，查看逐项结果。页面还显示当前运行数量、待恢复数量和可展开的名单。

## 恢复边界

- 只有记录器实际观察并确认 active 的本机桌面主对话进入退出快照；历史 inProgress 残留、子 agent、审核对话和其他设备不进入名单。安装前的历史退出不能自动补出准确名单。
- 已完成、已有新回合、已在运行或已归档/缺失的对话会跳过或提示核对。发送前先落盘回合收据，结果未确认时停止本批并保留记录，重复点击不自动重发。
- 向原对话提交固定继续指令，先核对进度与已完成操作，保持原模型、推理、权限、授权范围及停止条件；不替用户批准等待中的操作。
- 记录器不调用模型。点击续接后，原对话像正常消息一样使用模型额度。只读本机状态数据库，不读取登录令牌，不写 Codex 配置或数据库；完整转录不另存。
- 当前适配 Windows Store/MSIX Codex 桌面的本地 IPC。该接口可能随应用升级变化；适配出错时显示原因，不换成独立 CLI 或改权限。2秒采样不能保证突然断电前最后未落盘的状态完整保存。

## 状态与停用

状态保存在现行数据目录的 `codex/` 中：monitor.json 为退出快照，journal.json 为发送收据，operation.json 为最近一批实际进度与结果。真实名称、ID与设备路径只保存在用户本地，不提交仓库。

```powershell
& $progressPython scripts/task_progress.py configure-codex --state-dir '<现行数据目录>' --disable-codex
```

通过原服务入口重新启动使停用生效，快照与收据保留。看板动作仅接受同源、本机页面的短期请求标识；GET/自动刷新不会发送消息。

迁移已有独立实现时，先暂停其记录器，保留并复制 monitor.json/journal.json 到同服务的 codex/，核对文件后启用集成记录。停用旧独立启动入口；不删除历史记录或未验收的快照。

## 验证

自动测试覆盖状态迁移、跳过、防重复、未确认停止、真实HTTP处理规则和页面按钮条件。Windows上还应读回当前原生 active/idle 状态，浏览器验证页面功能；完整退出→重开→实际续接需要在已授权测试对话或用户下一次真实重开时验收。只读接口验证与模拟测试不等于这条链路已通过。
