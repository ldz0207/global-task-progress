# 共享项目的阶段进度快照

状态：设计讨论稿，尚未实现或启用。

本方案在现有本机看板之外增加阶段完成后的静态发布能力。共享目录的读者可以从项目入口查看最近一次已发布的进度，不需要连接执行者的电脑。实时数据继续由现有 Reporter 和看板维护。

## 已确定的需求

- 项目首页只保留名称和一句简介；点击项目后进入详细进度页。
- 一个项目可以包含多个器件或研究主题；执行任务需要明确归入项目与主题。
- 业务阶段完成后自动更新指定的共享目录，不随心跳或每次计数变化发布。
- 共享页面标明快照时间，包含阶段、实际计数、状态和相关成果入口。
- 本仓库维护通用实现、说明和测试，代码改动汇总到待审 PR。真实任务进度、项目资料和设备配置不进入本仓库。

## 建议的发布粒度

按可汇报的里程碑发布，例如一个候选版本完成设计、相关检查和资料交付。加载依赖、生成中间文件等内部步骤随快照保留，不各自生成一条项目成果。

执行任务完成不代表整个科研项目完成。页面中的完成数或百分比只描述相应执行阶段，不汇总成没有统一分母的项目总进度，也不把几何检查自动解释为器件性能验证。

是否允许另外指定较小的发布节点，保留为配置选择；默认采用上述里程碑粒度。

## 建议的数据与页面组织

| 层级 | 内容 |
| --- | --- |
| 项目入口 | 项目名称、一句简介、详情页链接 |
| 项目详情 | 按研究主题列出最近一次已发布里程碑、简短结果及成果链接 |
| 执行详情 | 展开查看来源任务的阶段名称、完成量、总量、单位和状态 |
| 历史 | 按里程碑或版本回查；默认收起 |

项目配置只描述归属、主题、发布目标和成果的相对链接。配置保存在使用者自己的运行环境；仓库仅提供虚构项目的示例。任务归属按配置确定，不从所有对话、任务标题或文件夹名称自动推断。

建议在指定项目目录中生成以下轻量成果，不新增使用者资料根目录：

```text
progress.html                 # 稳定的离线阅读入口
progress.md                   # 同内容的文本入口
progress.json                 # 最近已发布状态的结构化投影
history/<milestone-id>.json    # 各里程碑的发布记录
```

HTML 内嵌所需内容，使用相对成果链接和原生折叠元素。打开后不请求 localhost、远端服务或外部资源；执行电脑关机不影响阅读已保存的快照。

## 建议的触发方式

第一版采用显式的里程碑完成调用，接在业务验收与资料交付之后。调用一次即可读取已有阶段记录并发布页面，业务入口无需手工复制文件。具体方法名与参数在实现前确定。

```text
业务阶段验收与资料交付
    → 记录该里程碑已完成
    → 读取指定任务的阶段记录
    → 生成静态页面与数据
    → 写入配置的共享项目目录
```

不依赖额外的常驻轮询程序，也不修改现有服务的端口、数据目录、刷新频率或正在运行的 worker。配置之外的任务保持原有行为。反复读取或心跳更新不触发发布；相同里程碑的重复调用不能生成重复历史条目。

若后续需要自动捕捉已有任务的完成事件，再单独评估事件监听；它不能只依据任意子阶段达到 100% 就认定成果可以发布。

## 快照的数据范围

- 明确保存项目、主题、里程碑、来源任务 ID、源记录更新时间和发布快照时间。
- 保存相应任务的阶段名称、状态、真实计数与单位，以及业务提供的简短结果和成果链接。
- 不携带 PID、本机绝对路径、凭据、完整日志和未经筛选的任务数据；底层原记录继续保留。
- 静态页面不保留实时速度、当前 ETA 或自动刷新控件。
- 现有阶段记录不包含每个阶段的结束时间；缺失时间和历史耗时保持未知，不根据开始时间或当前读取时间补造。
- 进度记录是执行状态证据。科学结果与正式验收仍以对应项目的原文件为准。

## 写入与异常处理

发布前检查目标范围与成果链接，先生成完整输出，再更新稳定阅读入口。保留历史阶段；更新失败时继续提供上一份有效快照，记录待发布项，不能报告发布成功。

业务成果验收状态和共享发布状态分别记录：共享目录暂时不可用，不改变已完成业务的事实。恢复发布复用原里程碑标识，不重新执行业务任务。

共享页面的“最近发布阶段”与“实时执行状态”分别表述。阶段开始或正在修改时，旧快照仍清楚显示其保存时间，不冒充当前实时结果。

## 实施顺序与验收

1. 用虚构项目实现 JSON、Markdown 和离线 HTML 导出，验证项目归属、阶段计数与相对链接。
2. 接入可选的里程碑完成调用，验证重复调用、任务续接和共享目录不可用的处理。
3. 在使用者授权的一个项目目录试用，再修改其首页项目链接；实际配置与项目数据留在使用者环境。
4. 通用实现和说明提交待审 PR，按仓库规则运行相关测试；用户确认版本后再部署到已安装技能。

至少核对：未配置任务不发布、未完成里程碑不发布、项目和主题不混淆、同一里程碑不重复、缺失计数与时间不编造、HTML 离线可读、历史可回查、失败保留旧入口，以及发布过程不改变现有服务和任务源记录。

当前本 PR 仅记录设计；未修改 Reporter、服务页面、运行配置或业务 worker，未启动自动发布。
